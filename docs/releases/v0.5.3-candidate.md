# v0.5.3 release

Status: published and deployed on 2026-10-25 after the approved review. Runtime source: `47e3b98ce1f4fd4e06005f440d12211fad376b2a`. See `deploy/releases/v0.5.3.json` for immutable image/chart references and CI links.

Includes large logical CUDA copies using bounded host chunks, whole-range validation, 64MiB in-flight upload staging, mixed-version fallback to the old supported size, and bounded allocation-table address classification. Guest, broker and Worker must be deployed as a matched set.

Does not change Worker CPU affinity, shared-memory ABI, CRDs, HAMi quota, or default cache settings. Diagnostic tracing and experimental child selectors are excluded.

Functional validation on the prior candidate passed CPU tests, real-GPU copy boundaries, disconnect recovery, and Rodinia NW/LU output comparison. Final-package results are recorded separately in the deployment review.

Performance limitation: the previous complete 12-condition comparison did not establish a <=5% regression bound for every condition. Same-VM crossover: 6 PASS, 6 INCONCLUSIVE. A separate CPU-placement diagnostic improved small D2D/D2H latency but worsened asynchronous H2D by approximately 8%; that placement change is not included. These are copy latency results, not training throughput or Passthrough ratios.

Upgrade requires draining the affected VM's active client session before replacing the Guest/broker/Worker combination. Preserve the exact old artifacts, Helm revision and profiles. Rollback the whole combination; do not replace binaries during an active session. No promise of zero downtime or universal performance improvement.

Isolated Helm 0.5.2 install → 0.5.3 upgrade → rollback → candidate upgrade passed. A second isolated VM passed the standard Guest installer, config-drive bootstrap, systemd service, packaged PTX smoke and 18 copy cases.
