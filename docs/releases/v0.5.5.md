# v0.5.5 path-optimization release

Status: published and deployed on gpu-4, replacing v0.5.4 in `vmweave-test-a/vmweave-k8s-01`.

The release combines native memset, direct bulk input, reusable buffers, gather submission,
a host session arena, native Broker transport ownership, eventfd wakeups and a bounded pinned pool.
It preserves v0.5.4 fatal bulk-error fencing and environment-preserving installation.
The frozen measured candidate reduced completion time by 34.3% versus the bulk-enabled options-OFF
control, but took 10.0% longer than Flyt SHM overall. The user explicitly requested this deployment
following that result; the original experiment's conditional no-promotion decision remains historical.

The published Guest/Worker passed an isolated 50%/2 GiB GPU canary: 60 memset kernels, 18 large
sync/async copy cases through 128 MiB + 1, 140 alternating-stream enqueues, and NW/LU/SRAD/SC
output hashes matching native references. After replacement, production passed GPU and cache smoke,
math-mode checks, large copies and NW/LU correctness. These bounded checks are not a new performance
comparison or a concurrency soak test. GPU Compute Sanitizer remains unqualified because its earlier
instrumented Worker did not reach readiness.

Helm revision 13 uses chart 0.5.5 and a digest-pinned operator. The VM and root/SHM PVC identities,
GPU UUID, 50%/2048 MiB allocation, HAMi 2.10.0 and DRA revision 5 were retained. The old v0.5.4
Guest/configuration backup, Helm revision 12 and Profile/Request are retained for rollback.

The image source is tag `v0.5.5` at `2fd0461febbb481d187fa87de895537a14991f18`.
The follow-up main commit records deployment evidence and isolates a Python test fixture; it does not
change the deployed runtime sources or retag the images.

See [runtime settings and rollback](../runtime/path-optimization.md),
