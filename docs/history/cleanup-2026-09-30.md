# 기존 실험 환경 정리: 2026-09-30

이 페이지는 gpu-4에서 Go Operator 전환 후 수행한 정리 기록입니다. 일반 설치 시 만들어야 할 namespace 목록이 아닙니다.
[전환 직후 검증](../development/operator-validation.md) 이후 다음 작업을 완료했습니다.

- `flyt-gpu-validation`: 누락된 과거 guest 종료 기록은 임의로 생성하지 않았습니다.
  노드의 프로세스·파일 descriptor·메모리 mapping 사용 여부와 백업을 확인하고 관리자가 할당을 회수했습니다.
  구 Controller/Webhook과 관련 RBAC·namespace를 제거했습니다.
- `flyt-evidence-baseline`, `flyt-infra-validation`: VM 정의와 디스크를 보관한 뒤 VM·namespace와 전용 PV를 정리했습니다.
- `flyt-evidence`, `flyt-overhead-tcp`, `flyt-review-validation`: 기존 증거와 실행 중 VM 디스크를 보관했습니다.
  구 Channel 100개는 세대가 일치하는 Detached 증거와 회수 완료를 확인한 뒤 정리했고,
  새 API Channel 1개는 중앙 Controller를 통해 정상 삭제했습니다.
- 최종적으로 `flyt-*` namespace는 없으며, 기존 namespace의 전용 PV와 빈 backing 디렉터리도 제거했습니다.
- 중앙 release는 `vmweave-system/vmweave`, 관리 목록은 `vmweave-test-a`, `vmweave-test-b`입니다.
  두 namespace의 Webhook 요청, Controller/Webhook readiness와 노드 Ready를 확인했습니다.
- 구 `flyt.dev` CRD **정의**는 남아 있습니다. namespace 정리와 CRD 제거는 별도 작업입니다.

## 데이터 보존과 한계

원래 코드 백업은 `backup/pre-vmweave-operator-20260930` 브랜치입니다.
기존 디스크·산출물은 비공개 restic snapshot과 후속 정리별 archive에 보관했습니다.
클러스터 객체·VM 설정에는 민감 정보가 있어 공개 저장소에 원본을 올리지 않습니다.
온노드 백업은 원격 재해복구 복제본이 아닙니다.

Baseline 영구 디스크는 백업에서 읽어낸 전체 내용과 원본 SHA256 일치를 확인했습니다.
`basic-vm` 디스크는 독립 QCOW2로 복사하고 이미지 검사·체크섬을 확인했으나,
복사 중 지속적인 pause 및 애플리케이션 일관성은 입증하지 못했습니다.
마지막 `evidence-perf-preflight-t2`는 KubeVirt Paused 상태를 복사 전후 확인한 디스크 백업입니다.
두 경우 모두 메모리 snapshot이나 애플리케이션 복구 시험을 수행한 것은 아닙니다.

기존 성능 결과·UID·이미지 digest·체크섬은 당시 실험 기록으로 보존합니다.
namespace 삭제는 실험 증거 파일 삭제를 뜻하지 않습니다. 새 실험은
[신규 실험 가이드](../evaluation/new-experiments.md)에 따라 새 이름과 결과 디렉터리를 사용합니다.
