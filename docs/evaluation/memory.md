# VRAM 가용 경계와 두 VM의 메모리 한도


## 2026-10-16: 가용 경계·전체 계상 보완

단일 VM 10회, 동시 두 VM 10쌍, PyTorch 학습 계상 10회와 학습 상태 경계 추가 확인 2회를 측정했습니다.
초기 계상량 550 MiB가 한도에 포함돼 실제 사용자 버퍼 가용량은 다음과 같았습니다.

| 설정 한도 | 최대 성공 할당 | 다음 실패 요청 | 반복 |
|---|---:|---:|---:|
| 1 GiB | 474 MiB | 474 MiB + 4 KiB | 5/5 동일 |
| 4 GiB | 3546 MiB | 3546 MiB + 4 KiB | 5/5 동일 |

단순 CUDA 할당은 초기 비용과 할당별 4 KiB 올림으로 설명됐습니다.
동시 두 VM은 양쪽 최대 가용량을 유지하고 OOM 후 검산·재사용을 통과했습니다.
다만 PyTorch 학습 중에는 NVML Worker 사용량 764 MiB와 HAMi 계상 672.25 MiB 사이에
**약 91.75 MiB 차이**가 관측됐습니다. `empty_cache()` 후에도 allocator 사용량 64 MiB가 남았습니다.
추가 확인에서는 학습 후 잔여 논리 한도를 채웠을 때 NVML 사용량이 각각 **1116 / 4188 MiB**로,
두 설정 한도를 모두 **92 MiB 초과**했습니다(한도별 새 VM 1회). 다음 4 KiB 요청은 OOM이었으며,
논리 잔여량은 2048 byte였습니다. 즉, 논리 할당 상한 차단과 물리 프로세스 전체 사용량 제한은 일치하지 않았습니다.
설정값 전체를 사용자 버퍼로 보장하거나 물리 VRAM 전체가 빠짐없이 계상된다고 해석할 수 없습니다.

[실험 보고서·Grafana·스크린샷·그래프·원본](../../experiments/vram-accounting/README.md)

성공한 측정 VM 42개는 Released로 회수했습니다. 추가 시험의 최초 정렬 가정 실패도 별도 보존·회수했습니다. 기존 VM은 유지했습니다.
별도 준비 실패 1건은 GPU 실행 없이 Draining 메타데이터/backing이 남아 있으며,
정상 회수 수에 포함하지 않았습니다. 자세한 실패 원인과 범위는 보고서에 기록했습니다.

## 2026-09-29: 한도와 OOM 회복 확인

**2026-09-29, 독립 VM 쌍 3/3 PASS.** 동일 물리 GPU를 사용하는 VM A와 B에
서로 다른 한도를 설정하고 같은 크기의 메모리 할당 요청을 보냈습니다.

| 확인 항목 | VM A | VM B |
|---|---|---|
| 메모리 한도 | 1 GiB | 4 GiB |
| 1536 MiB 요청 | CUDA OOM | 성공 |
| A의 OOM 이후 | 같은 세션에서 128 MiB 재할당·검산·해제 | 기존 할당을 유지하며 검산 지속 |
| 종료 | Released | Released |

세 쌍에서 총 1,109개 요청과 4,436개 endpoint trace를 확인했습니다.
177회 표본 검산의 반복 합계는 정수 92,798,976개이며 불일치가 없었습니다.
이는 서로 다른 데이터 전체 용량을 뜻하지 않습니다.

## 해석 범위

이 실험은 특정 메모리 한도, 일반 OOM 이후 재사용과 상대 VM의 실행 지속을 확인합니다.
모든 장애의 격리, 악의적 커널에 대한 보안 격리, 연산 공정성 전체를 입증하지 않습니다.
