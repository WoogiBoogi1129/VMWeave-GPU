# 측정 이후 분석 처리 기록

측정 프로그램·전송 구현·바이너리는 `protocol.json`의 해시로 고정했다.
아래 변경은 분석·출판 처리에만 적용했으며 지연 표본을 수정하지 않았다.
최종 분석 스크립트는 `analysis-source/`, 최초 동결 스크립트는 `source/`에 있다.

1. 공개 원본을 gzip에서 XZ로 무손실 재압축했다. 압축 전 전체 바이트의
   SHA-256을 확인한 뒤 중복된 공개 파일만 제거했다. `packing.json`에 기록했다.
2. 측정 중 조기 Grafana 미리보기와 겹친 첫 SHM 조회에 대해 `exclusions.json`을
   먼저 작성했다. 첫 N/T/S 조회 묶음을 모두 보존·제외하고 새 세션 7에서 대체했다.
   원래 다른 조건은 유지했으며 대체 후 반복 확장 규칙을 적용했다.
3. UTC 정렬 검토에서 일부 VM의 `CLOCK_REALTIME` 간격과 측정의
   `CLOCK_MONOTONIC` 간격이 달랐다. 예를 들어 r3-T 첫 4 MiB 복사에서 약
   0.90초 차이가 발생했다. 부팅 시 1회 측정한 SSH 시각차를 전체 세션에
   적용하는 방식으로는 모니터링 구간을 정확히 대응시킬 수 없다.
   따라서 **모든 경로·모든 구간**의 Grafana/CPU 정렬에 실행 당시 이미 수집한
   `host-events.jsonl`의 시작·종료 로그 수신 시각을 적용했다. 호출 지연과
   처리율의 단조 시계 표본·완료 횟수는 그대로 사용한다. 각 구간의 차이는
   `clock-alignment-audit.json`에서 확인할 수 있다. 수신 시각에도 통신·스케줄링
   지연이 포함되고 양 끝에 공통으로 더해진 지연은 간격 비교로 제한할 수 없으므로,
   CPU 수치는 1초 counter 기반의 근사 관측치다.
4. 평균±표준편차 외에 세션별 median/p95와 전송률 그림, CPU 비용 표,
   N 기준 증가율·T 대비 S 변화율 원표를 추가했다. 서로 다른 경계나
   통계량을 빼서 순수 네트워크 지연으로 분해하지 않았다.
5. 사용자가 현재까지의 결과만 공개하도록 요청하여 확장 실행을 중단했다.
   r4-N의 6개 측정은 이미 끝났고 공개용 압축 중 SIGINT가 발생했다.
   온전한 원본에서 다시 내보냈으며 `additional-native/r4-N/export-recovery.json`에
   압축 전 파일 해시와 재내보내기 경위를 남겼다. r4-T/S 및 r5/r6는 미실행이다.
   본표는 N/T/S 각 3회로 유지하고 추가 N 자료도 별도 공개한다. 이는 성능에
   따른 선별이 아니라 사용자 지정 공개 시점과 비교 묶음의 완성 여부에 따른 구분이다.
