# 발표 자료 구성

측정이 끝난 뒤 생성한 표·그래프는 분석 자료이며, 실제 실험 화면의 대체물이 아니다.
터미널 캡처는 **원본 실행 로그의 사후 확인**, Grafana 캡처는 **실제 수집된 해당
시간대의 모니터링 조회**로 표시한다. 녹화본과 별도 결과 UI는 만들지 않는다.

1. **비교 조건 확인**: N/T/S 정의, 같은 물리 GPU UUID, 4 GiB, 단일 세션,
   CPU 배치, HAMi `DISABLE`/MPS 188 SM, trace off를 표로 제시한다.
   오른쪽에는 `identity.json`과 `runtime-libraries.json`을 조회하는 실제 터미널.
2. **측정 과정**: 터미널에서 `CONDITION → WARMUP → MEASUREMENT → RESULT`가
   이어지는 대표 실행 로그를 보여 준다. 시작/종료 시각, 실제 완료 건수,
   `mismatches=0`을 읽을 수 있는 글자 크기를 사용한다.
3. **제어 호출 비용**: `cudaMemGetInfo`, launch 반환, launch+sync 완료를
   구분한 그림. N은 호스트 직접 CUDA+HAMi 기준이며 순수 native 기준이 아니다.
   평균과 독립 실행별 점을 함께 표시하고 필요하면 로그 축임을 강조한다.
4. **데이터 전송 비용**: 4 KiB / 256 KiB / 4 MiB에서 H2D, D2H를 나눠 표시.
   CSV에서 산출한 완료 지연과 유효 전송률이며 물리 NIC 대역폭이 아니다.
5. **전체 처리율과 실행 상태**: resident/transfer 60초 완료 작업 수/초와
   실제 Grafana의 GPU 이용률·CPU·메모리·온도·클록을 해당 시간대로 제시한다.
   작은 CUDA 호출 지연은 Grafana의 1초 수집값으로 측정하지 않는다.
6. **검산과 해석 범위**: 모든 발표 수치의 원본 CSV/출력 파일과 검증 결과를
   연결한다. TCP+MPS와 SHM+HAMi의 전체 구현 경로 비교이며, 차이 전체를
   TCP/SHM 전송 매체의 효과로 해석하지 않는다. 느린 결과도 그대로 보고한다.

발표 화면에는 준비 실패 로그를 성능 실패로 섞지 않는다. 준비 실패는 별도
부록에서 호환성 수정과 최종 비교군 정의를 설명하는 데 사용한다.

이번 공개는 **기본 3회 비교 완료·확장 반복 중단** 상태다. 본 비교 63개 구간과
추가 N 6개 구간을 섞지 않는다. 발표에서 계획한 6회 검증을 완료했다고 표현하지 않는다.
