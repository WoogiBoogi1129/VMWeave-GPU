# 보완 실험 범위 — 2026-10-13

기존 E1/E2/E3/E4/P 증거를 수정하지 않는다. 이번 실행은 E2 단일 VM 쌍 예비 시험에 한정한다. 반복·성능 부하 보완은 자동 실행하지 않는다.

- 같은 숫자의 핸들 조건: 정상 자기 버퍼 읽기, 쓰기 후 자기 버퍼 첫 4바이트 및 나머지 4092바이트, 상대 버퍼 전체를 검사한다.
- 다른 세션에만 존재하는 핸들: A가 두 번째 4096바이트 합성 버퍼를 할당한다. B는 첫 할당만 유지한다. A의 기록된 핸들만 사용해 4바이트 읽기/쓰기를 각각 시도하고 양쪽 버퍼를 검사한다. 주소·핸들 탐색은 하지 않는다.
- 기존 등록 포인터 커널로 자기 주소 정상 실행을 확인한 뒤 대상 주소의 요청을 시험한다. 검증 경로는 변경하지 않는다. Guest 포인터 조회 결과와 launch 코드를 대조할 수 있으나 Worker 경계 계측 없이 정확한 거절 계층을 실측 확정하지 않는다.
- 데이터 노출·변조가 관찰되면 이후 시도를 중단한다. 새 코드의 자체 중단을 제품 차단 성공으로 세지 않는다. API 오류 뒤 세션이 정상인지 확인한 경우에만 다음 시도를 수행한다.
- 출력 판정은 경로별로 기록한다. GPU까지 실행되지 않으면 GPU 격리는 미검증이다. 기존 40회 결과에 예비 시험을 독립 반복으로 합치지 않는다.

향후 성능 예비 시험에서 부하 강도와 측정 시간을 확정한다. 허용 성능 저하 기준은 현재 미정이며 임의로 PASS 기준을 만들지 않는다. E4 시간 보완 2회는 별도 실행으로 보존한다.

## 999 원인 검토 및 분리 예비 시험

기존 B stderr에 `flyt rejected api=0x1012 transport_status=3`가 기록됐다. 계약상 3은 BAD_DESCRIPTOR다. `runtime/shm/src/guest.c`의 exchange는 이 transport 오류에서 broken=1로 설정하고 999를 반환하며 후속 요청은 broken 상태를 확인해 999를 반환한다. Worker의 copy_call은 해당 세션에서 참조를 해석하지 못하면 BAD_DESCRIPTOR를 반환한다. 개별 Worker 분기 자체를 계측한 것은 아니지만, 관측 응답과 소스가 일치한다. 따라서 기존 후속 check=999를 메모리 불일치로 해석하지 않는다.

분리 실행기는 읽기·쓰기를 각각 새 VM 쌍에서 한 번만 수행한다. 상대 버퍼 전체 검증, B의 후속 오류, stderr 응답을 수집하고 정상 회수한다. 예상과 다른 응답이나 회수 실패 시 다음 시험으로 넘어가지 않는다. 제품 코드는 변경하지 않는다.
