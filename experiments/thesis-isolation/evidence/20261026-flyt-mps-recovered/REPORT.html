호환 패치 Flyt MPS와 기존 VMWeave의 처리량 간섭 비교 — 선택한 3개 조건

비교 범위 변경: 결과 확인 후 사용자 요청으로 VMWeave에 불리했던 기존 메모리 부하(original/memory)를 본문·그래프 비교에서 제외했다. 측정 실패나 무효 판정에 따른 제외가 아니다. 이 문서는 사후 선택한 3개 조건의 기술적 비교이며, 전체 4개 조건의 우위를 주장하지 않는다. 제외 결과를 포함한 전체 조건 집계, 전체 방향별 집계, 원시 기록은 보존했다. 선택 기준을 참조한다.

선택한 3개 조건에서는 VMWeave의 평균 처리량 감소율이 Flyt보다 낮게 관측됐다. 이 문장은 선택된 조건에 한정하며, 절대 처리량 우위나 통계적으로 입증된 격리 우위를 뜻하지 않는다.

전체 실험은 Flyt 신규 10개 독립 VM 쌍·30구간을 완료했다. 원/확대 캠페인별 총 5회이며, 기존 VMWeave 각 10회 전체와 비교했다. 정상 완료 요청은 79,511건, 요청 오류·정확성 불일치는 0건이다. 최대 절대 오차는 5.81145287e-07이며 기존 rtol=1e-4, atol=1e-6 검사를 유지했다. 본문에 선택한 세 조건의 Flyt 평균 감소율은 +0.905~+8.913%이며, 기존 VMWeave와의 차이는 +0.590~+8.545%p다. 수치는 각 반복의 baseline 대비 감소율을 평균한 기술적 비교다.

선택한 조건의 처리량 감소율

캠페인 부하 VMWeave 감소율(%) Flyt 감소율(%) ΔD(%p) Flyt SD / 최소 / 최대(%)
original compute 0.315 0.905 +0.590 8.079 / -6.860 / 13.961
expanded memory 0.291 2.077 +1.786 8.727 / -12.504 / 10.472
expanded compute 0.369 8.913 +8.545 13.106 / -2.685 / 31.049

D=100×(1−동시 부하 처리량/같은 반복 baseline 처리량), ΔD=평균 D(Flyt)−평균 D(VMWeave). 감소율 단위는 %, 차이 단위는 %p다. D가 음수이면 baseline 대비 처리량 증가, ΔD가 음수이면 VMWeave보다 작은 감소율을 뜻하며 0으로 절삭하지 않았다. SD는 요청 단위가 아닌 독립 VM 쌍 간 표본 표준편차다.

선택한 세 조건의 Flyt 표본 SD는 8.079~13.106%p로, 기존 VMWeave의 0.091~0.144%p보다 컸다. 확대 연산 부하의 평균 감소율이 가장 컸지만 개별 반복에는 처리량 증가도 있어 일관된 감소라고 단정하지 않는다. 웜업 생략·짧은 관측·실제 부하량 등 조건 차이와 반복 변동을 함께 고려해야 한다.

부하 실행량은 각 부하의 실제 전체 실행 구간에서 완료 커널 수/경과 시간으로 계산했다. Flyt 부하 목표 130초, 관측 목표 120초이며 준비 이후 부하가 관측 종료까지 계속됐음을 기록으로 확인했다. 기존 VMWeave 부하도 보관된 load 완료 기록으로 재집계했다. 커널/초는 시스템 간 동일한 GPU 점유율을 뜻하지 않는다. 제출 경로·작업 배출 속도 차이는 간섭률 해석에 포함해야 한다. GPU/CPU 원시 telemetry는 입력 manifest와 raw 자료에 보존했다.

Flyt 패치는 진입점 조회, PCI 탐색, 내부·구조체 포인터 보존, 필요 커널의 지연 조회를 포함한다. 실제 GPU 가상주소를 보존하는 이 시험 빌드는 체크포인트·이동을 명시적으로 거부하며, 일반 배포 또는 모든 CUDA API 지원을 검증한 것이 아니다. 호환성 복구 보고서에 근거·패치·검증·제한을 분리했다. 기존 VMWeave 패키지와 결과는 수정하거나 삭제하지 않았다.

원 P 첫 세 반복은 부하 커널 동기화 후 완료 이벤트를 받았지만, 그 뒤 버퍼 삭제·캐시 회수까지의 별도 확인 응답은 없었다. 나머지 7회에는 대기열에 observe 0 제어 명령을 보내 회수 뒤 응답을 확인했다(요청 0개, GPU 연산 없음). 첫 세 반복의 조건 전환 시 회수 작업 중첩 여부는 로그만으로 확정할 수 없다. 해당 표본을 제외·재측정하지 않고 모두 주 집계에 포함했으며, 이는 절차 차이와 해석 제한이다.

ΔD는 이번 조건에서 관측한 차이이며, MPS 자체의 인과 효과나 시스템의 일반적 우열을 확정하지 않는다. 측정 시점, 실행 경로, 실제 부하량, 웜업, 관측 길이, SHM 및 호환 패치 차이가 함께 포함된다. 작은 차이나 음수 감소율을 무간섭·동등성으로 해석하지 않는다. 본문·도표에 지연시간 백분위수 비교는 포함하지 않았다. 기존 요청 기록의 start/latency는 결과 검증·출력까지의 정확한 완료 시각을 제공하지 않으므로 과거 첫 120초를 잘라 별도 표본으로 사용하지 않았다.

방법·검증·재현

  • 각 반복은 새 VM 쌍과 독립 세션을 사용했다. 3조건 순서는 고정 seed로 사전 결정하고 가능한 범위에서 위치를 균형화했다. protocol.json에 방향과 순서를 모두 기록했다.
  • 진단·호환성 검증은 본실험에 합산하지 않았다. VMWeave는 신규 실행하지 않았으며 원본 각 10회를 임의 선별하지 않았다.
  • 원시 요청 수, 정확성 코드, 경과 시간, 부하 완료·관측 종료 순서와 CSV를 교차 검산했다. validation.json, cleanup.json, source-sha256.json을 참조한다.
  • 그래프는 같은 CSV/JSON에서 PNG·SVG·PDF로 생성했다. 오차 막대는 표본 SD이며 신뢰구간이 아니다.
